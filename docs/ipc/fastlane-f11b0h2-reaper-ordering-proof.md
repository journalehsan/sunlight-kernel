## Source call graph and authoritative boundaries

* SunlightD `stop_service` requests SIGTERM, observes exit/gone, and may escalate or report failure/timeout; confirmed exit is reconciled before replacement (`services/sunlightd/src/main.rs:1286`). A signal request is not an exit commit. `finish_current_process` takes `SCHEDULER`, marks the process Finished and `exit_cleanup_pending`, and for an eligible non-Linux-worker calls `close_owned_ipc_endpoints` (`kernel/src/sched/mod.rs:4226`, `:4298`, `:4319`). This self-exit path takes `CAP_BROKER`, removes endpoint capabilities and retires recipient/session grants, then removes each IPC queue and finishes peer calls (`:2631`).
* External termination and `apply_pending_fatal_signal` mark Finished under scheduler serialization and either reap immediately when not owning a CPU or request rescheduling and defer (`kernel/src/sched/mod.rs:3108`, `:3173`). `reap_process_resources` waits for no owning/queued CPU, pinned stack, active address space or live borrowers before removing PID references and endpoint queues, finishing peer calls, and only then revoking endpoint capabilities and retiring broker authority (`:2646`, `:2787`). Both paths are conditional; normal exit, fatal signal, and reaper cleanup must not be assumed interchangeable. The original pending-fatal-signal log and observed order are consistent with the second path but do not contain an explicit path marker.
* `finish_peer_closed_calls` matches PID/incarnation and pending endpoint/call generation, invokes `finish_call`, settles undelivered grants and clears the pending call before marking `PeerClosed` (`kernel/src/ipc/mod.rs:1904`, `:993`). A peer-close notification is neither broker row removal nor sessiond completion. Self-exit and reap both operate on a scheduler borrow; the shard and broker guards are scoped as in source, rather than held across a blocking barrier.
* Sessiond `begin_stop` requests broker revoke before stopping children; `finalize_stop` requests revoke again, moves active state into `last_closed`, and logs logout (`services/sunlight-sessiond/src/main.rs:586`). Both ignore transition errors. Its loop also synchronizes authority according to local state (`:192`, `:1579`); local metadata is not broker authority and a logout log alone is not an epoch-qualified cleanup receipt. The fixture has not proven unaffected unrelated sessions or bounded global cleanup.
* Broker `revoke_endpoints_owned_by` removes endpoint records and capabilities, then `retire_recipient_grants` calls `retire_sessions_for` and removes pending issuer-bound and recipient-bound grants (`kernel/src/capability/mod.rs:1021`, `:1053`). Session row removal also removes its Account grants (`kernel/src/capability/sessions.rs:231`, `:251`). Delivered VFS grants have distinct recipient-owned lifetime semantics; they are not all revoked simply on issuer exit. VFS delegation consumes a suitable proof and inserts bound grant rows under scheduler and broker serialization (`kernel/src/capability/lifecycle.rs:133`, `kernel/src/capability/vfs_grants.rs:6`).

## Safety analysis and limits

Invariant: no authorization or publication may derive fresh authority from an authoritatively invalid issuer; stale endpoint, request or service identity must not transfer authority to its replacement. Authorization, broker commit, delivery and subsequent consumption are distinct. `sys_account_grant` obtains `SCHEDULER` across identity checks and broker commit (`kernel/src/arch/x86_64/syscall.rs:1685`); `grant_requester_for_role` rejects `is_exiting`, and `account_grant` checks live session participants before `commit_account_session_grant` (`kernel/src/capability/lifecycle.rs:86`, `:380`). Thus, on the audited reap path another ordinary Account commitment cannot acquire the scheduler between peer-call cancellation and session retirement. This is source-level serialization evidence, not the requested native competing-boundary proof, and does not prove all IPC or VFS outcomes. Role flag storage need not be cleared at Finished for an exiting process to fail the live issuer check.

A commit before retirement can be valid; an undelivered grant bound to a closed call is settled by cancellation, and session retirement removes associated Account grants. A delivered VFS grant can have a different lifecycle. A serial line or the relaxed E3 sequence counter by itself does not establish cross-CPU happens-before. Both peer-close and broker retirement markers in the original trace are on CPU 1, but missing path and publication checkpoints still limit the inference. The necessary H2 fixed-size bounded trace, path discriminator, true endpoint-removal event, publication outcome, and epoch-qualified sessiond completion were **NOT IMPLEMENTED**; the archived E3 logging is not the requested H2 event buffer. No H2 schema or revised parser version exists.
