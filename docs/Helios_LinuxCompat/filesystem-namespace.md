# Unified Linux filesystem namespace

Decision proposed: make the VFS service the single authority for the mutable mounts visible to Helios. Cut over by mount, with all readers and writers of that mount switched together. Keep kernel virtual endpoints and an explicit immutable bootstrap source. The current service can host the authoritative tree, but its existing RPC and RAM root do not yet provide the necessary Linux semantics or recovery.

## Current routes (source verified)

Entry points: [Linux translation table](../../compat-linux/src/lib.rs#L375), [kernel syscall dispatch](../../kernel/src/arch/x86_64/syscall.rs#L1284), and the handlers named below. K means the kernel's live VFS; S means the service's separate live VFS. Native handlers named here are included only where Linux uses them.

For K path operations, the syscall supplies current process credentials and/or the kernel-derived policy actor as specified below. There is no service endpoint, epoch or retained namespace admission on these paths. Relative paths generally use the shared process cwd string; legacy *at resolution uses a kernel directory handle's path for a real dirfd. That string is not a retained directory object. For S pathname operations, the kernel captures the authenticated registration, caller incarnation and credentials; the service checks the retained root/cwd scope and operation grant. A shared cwd transition also ties the waiting task to its shared process owner and checks credentials. S handle operations use the current fd table and operation rights, plus the authenticated service registration and open-file ownership. A local fd number is not a service credential.

| Linux operation | Route and owner | Checks and handle/metadata dependency | Changes |
| --- | --- | --- | --- |
| mkdir, mkdirat | Both normalize into `sys_linux_mkdirat`, K | Kernel resolves *at path, rejects procfs, applies Mkdir write policy and passes uid/gid and mode to K | Directory entry and inode |
| open, openat | `sys_open` / `sys_linux_openat` → `open_resolved_path`, K by default; separately selected file route uses S | Kernel parses Linux flags and enforces path and credential policy on K, including restricted broker store; fd rights derive from access mode. S uses scoped open and currently supports existing regular files only. Procfs and Linux null device have dedicated kernel routes | Lookup; conditional create/truncate on K |
| creat, O_CREAT | Standalone creat unmapped; open flags initiate K create | Write policy and kernel VFS create; exclusivity must be decided at insertion. S does not implement this path | Entry/inode, and possibly content |

| read/write, readv/writev and pread/pwrite | Native I/O handlers and Linux vector/positional shims dispatch by fd; K, S, or kernel objects as applicable | Kernel fd rights and description state; S calls validate operation and server token ownership. Pipes, sockets, memfds, procfs and null retain their own semantics | Writes change bytes, size and potentially metadata; no entry change |
| statfs, directory/metadata adjuncts | Linux statfs shim; kernel virtual and K bookkeeping; statx, renameat2 and fsync/fdatasync absent from translation | Supplement with explicit mount reporting, sync guarantees, and unsupported errno tests at cutover | No namespace changes |
| close, dup, fcntl, seek, mmap, exec | FD lifecycle/offset or image paths in syscall layer; close/seek support service file descriptors where implemented | Audit backend behavior individually, including backing references, append flags, executable lookup and file mapping. An unmigrated consumer must reject the migrated object or use its real authority | Usually no directory change; exec can change process incarnation |

It contains no affirmative evidence of endpoint registration loss, exec incarnation replacement, anchor retirement, or service restart as the trigger. A baseline replay can hold the retain acknowledgement across existing first execution; a migration replay must prove execution stays blocked until publication. Separately withdraw or replace an existing binding. Record the exact caller incarnation, service incarnation/epoch, absent versus rejected binding, readiness and retain request ID at each step. Do not collapse these causes into an assumed transient errno. Use the ordinary-child publication contract below. Reject stale authority; never reroute it to K.

## Readiness and child publication

### Confirmed boot and launch behavior

[Kernel boot](../../kernel/src/main.rs#L892) loads init directly, marks it for boot-root metadata retention and passes the spawn capability. It separately loads the trusted embedded VFS server with the boot share mapping and, when a framebuffer is available, tty_server with its framebuffer mapping. Neither service inherits a parent binding. [Init](../../services/init/src/main.rs#L117) runs the nameserver and drains REGISTER/LOOKUP while probing authenticated root metadata. [VFS startup](../../services/vfs_server/src/main.rs#L201) synchronously registers its endpoint as “vfs” with init, then builds its mounted namespace and obtains and binds the authenticated kernel registration snapshot before draining retention. Naming the endpoint is not proof of namespace readiness. The [retention transport](../../kernel/src/ipc/vfs_registration/transport.rs#L7) stages init's boot-root retain; the authenticated retained reply installs its binding. Init then runs storagectl and the base service launches. Gating init before its first instruction would stop REGISTER from completing and thus stop the retain that could satisfy the gate. The current root probe loop has no overall failure deadline.

[Inheritance](../../kernel/src/ipc/vfs_registration/inheritance.rs#L11) captures only an already admitted binding and pins the exact source receipt by strong reference until derivation settles. Parent exit, successful exec or root/cwd change does not itself revoke that snapshot; service retirement does invalidate its epoch. Target validation uses PID, incarnation and VM generation plus credentials and expected cwd. Provisioning currently returns no outcome to spawn, and both spawn paths enqueue and return success without waiting for installation. Neither sticky route flags nor a queued retain is proof of a live binding.

### Proposed bootstrap boundary

Authorize only the kernel-created embedded init incarnation and VM to run its bootstrap control plane before binding: process the nameserver's capability-checked REGISTER/LOOKUP traffic, service timers/control IPC, and probe authenticated root readiness. The only pre-binding namespace setup is the kernel-authorized metadata-only root/cwd retain; the probe fails closed until it can use the installed binding. Deny ordinary spawn, namespace traversal, mutation, and fallback to the kernel tree during this phase. Loading the boot images from the immutable seed is a separate kernel operation. PID 1 alone, uid 0, image name, executable path, possession of a spawn token, or descent from init must not confer the exception. Exec and exit withdraw bootstrap identity. Service initialization and tty device setup have their own narrow rules below.

Activation requires the matching installed live binding in the active epoch; the successful root probe is init's observation, not the authorization event. Registration rejection, retain refusal, or expiry of a bounded overall boot deadline leaves init in degraded control-plane mode with a reason in serial diagnostics and no ordinary launches. Leave nameserver/control traffic available for diagnosis; do not spin on root lookup or silently retry retention. Replacement invalidates the old binding and blocks launches immediately. Reprovisioning requires a separately authorized fresh registration and explicit recovery decision; first stage does not replay the bootstrap grant or revive pending children.

### Parent admission policy and observable ABI

After validating the request and existing launch authority, check the actual execution caller's state and the current authenticated service registration, then validate and pin its exact live binding and snapshot cwd and source grants. Do this before child allocation, attachment consumption, descriptor transfer, or launch accounting. A supplied session, recipient or parent PID cannot select the inheritance source. An active service with an absent, withdrawn or obsolete parent binding fails immediately with `NamespaceNotReady`; there is no child identity, retain, readiness waiter, or retry. Only already admitted work may park awaiting its receipt. Apply this rule to every ordinary call through either adapter, even for a native executable with no VFS profile enabled at launch. Exempt only the explicitly authorized direct boot and independent server setup paths below; a named service launched by an ordinary adapter still inherits.

The [native decoder](../../sunlight-libc/src/sys.rs#L135) understands the native sentinel words, not Linux negative errno in general; unknown words currently become successful counts/PIDs. The [IPC adapter](../../kernel/src/arch/x86_64/syscall.rs#L1947) currently emits `ERROR` with an internal `SpawnError` ordinal or a bare `ERROR`. Ordinals are not errno; preserve legacy unrelated failures and do not renumber them. Proposed structured readiness errors use `SpawnMsg::ERROR`, `word_count=2`, `words[0]=0` (bare-error placeholder), `words[1]=positive errno`, `cap_count=0`; consumers key on label and count. Structured errors cover the following coordinator decisions; existing pre-admission IPC transport/authentication failures and unrelated image/argument failures keep their ABI. Success stays native PID in `rax`, or IPC `REPLY` with two words `[PID, VM generation]`; failure yields no PID/generation. The capability syscall returns transport success for a structured `ERROR` reply.

| Coordinator condition | Native raw result (`M = u64::MAX`) | IPC detail |
| --- | --- | --- |
| Parent unbound in active epoch | `M-1` (`Again`); a new attempt is caller initiated | `EAGAIN` (11) |
| Invalid live process state (no eligible execution context for admission) | `M-5` (`Inval`); dead/replaced caller gets no reply | `EINVAL` (22) when reply remains possible |
| Launch permission/authentication denied | `M-3` (`Access`) if reported by coordinator | `EACCES` (13) |
| No active authenticated service | `M-13` (`NotConnected`) | `ENOTCONN` (107) |
| Reservation table/identity capacity or memory/account quota exhausted | `M-11` (`NoSpace`) or `M-12` (`NoMemory`), respectively | `ENOSPC` (28) or `ENOMEM` (12) |
| Authenticated retain refusal | `M-8` (`EIO`, currently `Failed` in libc); log correlated refusal status | `EIO` (5) |
| Acknowledgement deadline reached | `(-110i64) as u64` (`TimedOut`) | `ETIMEDOUT` (110) |
| Admitted epoch retired before commit | `M-13` (`NotConnected`) | `ENOTCONN` (107); trace epoch retirement separately |
| Explicit pending-child/kernel cancellation | `(-125i64) as u64` (`Canceled`) | `ECANCELED` (125) |

**Approval required: ABI rollout.** Reuse established errno numbers; no new errno allocation. The two negative words extend native spawn's accepted wire results: stat transport already uses `-110`; `-125` is the existing errno for cancellation. None of the existing decoded native words distinguishes timeout and cancellation from the other required results. Extend the spawn decoder and raw callers before enabling the gate; for old binaries use an explicit spawn ABI opt-in or prove all supported binaries are rebuilt together. Never send a new failure word to a legacy decoder that could return it as a PID. Reject out-of-range PIDs in updated decoders. Confirm structured IPC details against legacy ERROR consumers, including wrappers that collapse errors; a user-facing message need not expose the number but must preserve failure and avoid retry loops.

### Capacity, acknowledgement deadline and drain

Use the existing [per-registration ownership budget](../../kernel/src/ipc/vfs_registration.rs#L25): 64 remote leases shared by live, pending and compensating ownership. This is a ceiling, not 64 extra pending children. Reserve a real lease/binding slot, pending record, continuation, scheduler slot and cleanup credit together before allocating a child; at most one outstanding spawn per calling task. Share the fixed budget with existing admissions and reserve the init control retain before permitting ordinary admission. Also debit existing account/session/process allocation quotas and memory budgets while pending; no borrowed or uncharged child VM. Reject capacity immediately. Do not use telemetry limits or the unrelated stat request table as extra capacity. One delivered retain at a time per registration; no retain retransmission after delivery or copy uncertainty ([transport](../../kernel/src/ipc/vfs_registration/transport.rs#L265)). Polling NEXT or draining release obligations is not a second registration attempt.

**Approval required: deadline and escalation policy.** Use one fixed five-second monotonic budget (`5 * TICK_HZ`, 500 ticks at the current 100 Hz), starting at reservation and covering construction, queue delay and acknowledgement. Reuse the [stat/file convention](../../kernel/src/ipc/vfs_registration/file.rs#L10), with wrap-safe elapsed comparison and expiration winning at equality even if the timer worker has not run. Apply the same five seconds separately to init from first bootstrap dispatch through authenticated binding activation; this is a proposed boot budget, not measured boot latency. Test cold boot and caller end-to-end deadlines before enabling it. A pending child loses authority at deadline and local resources move immediately to teardown; it never waits for remote drain. Use one existing ownership slot per delivered abandoned request (and reserved local cleanup credit); work is limited to the fixed table and existing per-child quota, with no unbounded tombstones or timer-context VM destruction. Allow up to one further five-second drain interval from cancellation for an already delivered request and any compensating release ACK. At expiry, fence and retire the stuck epoch via authenticated registration teardown, even if the service process is still alive. Undelivered entries need no drain interval. Process cleanup outside timer/transport locks through the existing reaper; do not recycle its credit until reclaimed. A timeout never extends on partial progress or resubmits a request.

### Publication and ownership

| Transition | Owner and required action |
| --- | --- |
| Request accepted → pending inheritance | Shared kernel spawn coordinator owns the exact child, parent reply ticket, launch reservations, source pin, desired CPU placement, and monotonic deadline. Reserve pending and cleanup capacity before handing work to VFS. Build the child with a reserved identity; expose it to authenticated retention validation and lifecycle cancellation only. No runnable state, PID success, public waitable child, or success-only launch notification. |
| Pending → retain submitted | VFS runtime owns the request ID, derivation pin and single-delivery transport; associate exact registration and epoch, target PID/incarnation/VM, scope and request ID with the pending record. Queue/prepare failure cancels synchronously. |
| Receipt → binding installed → runnable | Existing authenticated VFS transport validates the submitting endpoint/service identity, delivered ID, scope/receipt and target identity, credentials and cwd; VFS runtime installs the binding. The coordinator and scheduler linearize install and publication against termination, timeout and epoch retirement, rechecking the exact binding and active epoch. Installation is internal until the scheduler consumes the pending slot and enqueues exactly once. Reserve a reliable publication path in advance; if commit fails, withdraw the installed binding and compensate. No unlocked interval with an unchecked publish token. |
| Pending → cancelled | The coordinator claims the terminal transition once on authenticated refusal, local failure, deadline, explicit child cancellation, or service loss before publication. The scheduler cannot enqueue a cancelled identity through wakeups, signals, normal ready scans or stale slots. If termination races successful publication, the winner under the lifecycle lock determines whether this is pending rollback or normal live-process termination. |
| Terminal outcome → report and cleanup | Coordinator completes the exact original syscall/IPC continuation at most once, only if its caller incarnation/VM and reply ticket still match. Report PID and generation only after publication; encode failures using the ABI table. Scheduler/resource owners release pending identity, VM, stacks, descriptors, capabilities, session/account/TTY reservations and launch accounting exactly once, using existing teardown where applicable. Drop or retire the parent continuation separately. |

Before capture, parent death or identity change makes admission fail. After capture, parent exit or exec abandons the old reply ticket but does not cancel the child or drop its source pin. On publication use existing orphan handling for a dead parent and generation-aware parent/session attribution captured at admission; do not inherit again from a reused PID. Explicit child termination, including a separately authorized group/session cancellation targeting the pending child, can still cancel it. Preserve existing session and capability revocation rules; possession of the source pin does not preserve unrelated launch authority.

Invalid or unrelated receipts never advance or cancel a valid preparation merely by arriving. For a cancelled delivered request retain bounded cleanup bookkeeping keyed by epoch/request identity. If the authenticated service created a receipt, use the existing abandon/compensating release path, with one release obligation per uninstalled receipt and no release of the live receipt on duplicate delivery. Undelivered work can be removed without remote release; authenticated refusal creates no retained object. Reconcile source pin release on settlement. Cancellation must not strand the single-delivery channel: settle the delivered request or retire the epoch before advancing past it; reserve cleanup capacity, and define bounded escalation to epoch failure if the live service never settles. Retirement cannot make old handles valid on the new service; retire old transport obligations under existing epoch teardown and never send their release to the replacement. Reclaim local child resources even if remote cleanup remains outstanding.

### Shared scheduler publication API

The following are internal interfaces and ownership rules; neither adapter may call generic enqueue on a pending identity:

| Operation | Preconditions and result |
| --- | --- |
| `reserve_spawn(caller, authorization, reply_kind, placement) -> Reservation or SpawnFailure` | Under lifecycle serialization, validate and pin source and reserve all credits. Return an exclusive reservation tagged with the exact caller identity and epoch. No child is visible. Dropping or aborting the reservation runs the same rollback path as submission failure. |
| `submit_spawn(reservation, staged_child, staged_effects) -> Parked or SpawnFailure` | Transfer ownership into the private pending table, attach the retention request key and register the reply/park continuation atomically with making work eligible for delivery. No raw user pointers survive; retain a saved return frame or equivalent task-owned continuation. A ready completion racing park must latch the result and prevent a lost wakeup. |
| `settle_spawn(key, authenticated_outcome, now) -> Published, Cancelled, or Ignored` | Internal transport entry only. Key includes pending slot generation, epoch and request ID; verify delivered request, exact server endpoint/incarnation, target PID/incarnation/VM, saved scope, credentials and cwd. At or after deadline use timeout. On success install binding, apply prevalidated launch effects, transfer child to the live table and enqueue under one lifecycle/epoch critical section; enqueue is the commit point. Pre-reserve capacity so no fallible allocation or user copy remains after commit. On precommit failure withdraw any installed binding and route the receipt to compensation. Refusal cancels; malformed, mismatched and duplicate outcomes do not change the pending child. |
| `cancel_spawn(key, reason) -> Won or AlreadyTerminal` | Exact identity only. The terminal winner detaches resources and reply once. A lost cancellation never rolls back a published process; normal termination must use the live identity. `retire_epoch` fences admissions and invokes this path for each matching record before replacement activation. |
| `finish_spawn(reply_ticket, result)` / `reap_spawn(cleanup_credit)` | Consume detached ownership once outside transport critical sections; revalidate the caller ticket under scheduler before writing the saved result or waking it. A dead task or exec invalidates the reply, including a result latched but not yet delivered. Local cleanup and remote release accounting have separate lifetimes. |

Serialization order: scheduler/lifecycle → PMM when image construction or teardown needs it → capability broker → VFS runtime. Publication needs scheduler → broker → runtime, without PMM; never acquire PMM with runtime or broker held. Preserve the existing scheduler-before-PMM order in both adapters. If receipt decoding begins under a transport lock, drop that lock before entering the coordinator and revalidate the key and epoch under the ordered locks; a decoded receipt alone cannot commit. Epoch retirement must use the same lifecycle serialization, including exit/exec hooks. No synchronous registration IPC, wake callback, final reference drop that re-enters these locks, or reaper call while holding runtime/broker locks. Stage notifications and deferred drops for dispatch after unlocking; a scheduler wake that requires the scheduler lock is performed with the existing locked helper or after release, never by recursive acquisition. Timer processing marks expired entries and schedules bounded reap work. Check that init's parked launch cannot block service retention: endpoint registration and init retain must already be complete, and the retention server must get independent scheduler progress without another synchronous init call.

### Service replacement and init reprovision

Retirement closes old epoch admission and cancels unpublished children with `NotConnected` before new activation. Invalidate old bindings and service descriptors; already runnable children remain live, fail closed for obsolete service authority and cannot spawn through it. Preserve unrelated descriptors and kernel virtual endpoints. Never substitute the same path in the replacement tree for a retained object. No transparent child rebind or replay; descendants need a fresh authorized launch from a newly bound parent. Late old epoch replies cannot install anything even if endpoint/PID numbers are reused; compensate only while the old authenticated epoch still owns the obligation, otherwise discard under its retirement.

**Approval required: live recovery.** Stage one leaves surviving init in degraded nameserver/control mode after retirement and requires reboot for production recovery. If live recovery is approved, a separately authorized loader activates the replacement only after old-epoch fencing and backend initialization. A kernel recovery grant may authorize one fresh metadata-only root/cwd retain per replacement epoch for the same original embedded init incarnation/VM, provided it is still live and has not execed or rebased its root; no other paths or grants revive. Bind it to the new authenticated registration, start a fresh boot-policy deadline, and consume once on submission. Definitive refusal, timeout or identity loss leaves init degraded. Only matching binding installation and a successful authenticated root probe let init resume ordinary launch; reconcile old supervised instances before issuing explicit fresh launches. There is no automatic recovery grant or namespace migration.

### Both spawn paths and compatibility

[Capability spawn](../../kernel/src/process/spawn.rs#L1002) provisions then uses generic `enqueue_ready`; its [syscall adapter](../../kernel/src/arch/x86_64/syscall.rs#L1855) returns REPLY/ERROR and performs session and launch bookkeeping. [Native spawn](../../kernel/src/arch/x86_64/syscall.rs#L4590) independently provisions, enqueues on the caller CPU, and returns the PID. Both must invoke the same admission/commit coordinator; adapters keep ABI, image construction and placement policy (generic selection versus captured CPU with existing offline handling). Stage success-only bookkeeping before publication with rollback, and defer success reporting and trace milestones until commit. Do not alter general runnable selection. The current insertion API alone is insufficient: it leaves a Ready process in the table and derives foreground data from a PID lookup. The missing primitive is bounded **unpublished process ownership** with exact-identity resolution for VFS and cancellation, scheduler exclusion, a one-shot commit/rollback under lifecycle/epoch synchronization, and a generation-bound deferred spawn continuation for both adapters. No holding scheduler/broker locks across service IPC and no syscall rewind that creates another child. Live exec's existing transfer/withdrawal is separate from spawn; a process that loses binding on exec cannot spawn until explicitly ready.

### Decisions and evidence limits

Source confirms the handshake dependency and the enqueue-before-install behavior. Host assertions cannot establish first dispatch. The stage-one fail-fast scope is selected. The remaining approvals are the ABI rollout, reuse of the shared capacity budget and proposed deadline/drain policy, and optional live recovery. TTY remains device bootstrap only; any future client namespace use needs a separate authorization and acceptance case.

Implementation order: (1) resolve ABI and budget approvals, (2) add private scheduler reservations, reply tickets and rollback, (3) connect authenticated retention, epoch fencing and deadline/drain ownership, (4) wire both adapters and update callers/decoders, (5) pass host transition tests then native guest acceptance, (6) add live recovery only if independently approved. The mount and service contract work below is outside this readiness change.

## Separate ring-0 VFS ownership audit

`python3 tools/audit_vfs_cutover.py --no-growth` reports three additions. [Linux statfs](../../kernel/src/arch/x86_64/syscall.rs#L6218) reads FAT capacity from the live kernel VFS by mount ID and [procfs mountinfo](../../kernel/src/linux_procfs.rs#L173) reads the live kernel mount view to synthesize output. Both are real consumers even though they report metadata. [Storage FAT mount](../../kernel/src/storage.rs#L123) is a real existing kernel mount path, but the reported **addition** is an exact-source false positive for new ownership: the existing constructor now binds `mut fat` to sample capacity before passing it to the same runtime mount. No new backend owner follows from that line change. Preserve all three observations, functionality and the audit baseline; address real reads when transferring their mount's authority.

## Ownership contract and recovery boundary

Use the service mount and its object IDs for path lookup, mutation and enumeration. Kernel owns user memory, Linux ABI conversion, credentials, authorization to use each RPC, process/VM lifecycle, fd table and rights, and authenticated endpoint transport. Carry a versioned request bound to service incarnation/epoch, caller incarnation, VM generation where required by the existing completion contract, scope generation, and operation ID. Send a raw path relative to the retained root/cwd or a directory token from the fd table, not a kernel-reconstructed absolute path. Validate both parents in one request for rename/link, enforce search and write policy against resolved objects, and enforce mount boundaries including EXDEV. Derive any privileged actor from trusted kernel policy, not caller names or caller-supplied credential claims. Use explicit grants for lookup, enumeration, open, creation, deletion, rename and attribute change. Revalidate at execution and completion as appropriate; cancellation cannot claim a mutation never ran after its commit point.

Keep open descriptions and directory pins distinct from name bindings. Unlink and rename replacement withdraw names while pinned objects remain usable; metadata-profile withdrawal must preserve already-open rights (covered by service runtime tests). Last close and caller-owner teardown retire references exactly once. Registration withdrawal retires that service epoch's requests and handles. Never rebind an old fd to a new inode at the same path. Define and test bounded admission, reservation before irreversible mutation, late completion handling, and outcome deduplication for any retry after dispatch. Preserve descriptor sharing across dup and threads, CLOEXEC and current image/VM validation. Return a deliberate error on unknown outcome rather than silently replaying a mutation into a replacement epoch.

[Service startup](../../services/vfs_server/src/main.rs#L377) constructs RAM views from INITRAMFS; its live root is mounted from the seed in the ram branch. [Kernel startup](../../kernel/src/main.rs#L2475) mounts its own Tmpfs using BOOT_INITRAMFS. Seed files/directories are the compiled RamEntry set (including implicit parents); service mounts from configuration are separate from that seed. Entries made by runtime create/mkdir, rename destinations, deletions, changed attributes and written bytes are live state. The current kernel-created Git fixture is in K and cannot be reconstructed by restarting S. If mutations are moved to S, restarting a volatile S likewise loses those changes. Service memory holds object/handle state; a new registration cannot honor old handles or recover old cwd by path. Existing metadata withdrawal survival in a live service is distinct from registration retirement and process death.

For volatile cutover, specify destructive restart: stop admissions, retire old continuations and service descriptors, expose a fresh mount identity only after initialization, and require explicit reprovision/reopen. Preserve virtual objects and unrelated fd backends. If state must survive restart, require an authoritative persistent backend or replayable transactions before advertising durability; a disk mount alone does not make the RAM root recoverable. Persist directory/inode identity, link counts, attributes, content, and mount identity with atomic rename and defined file/directory sync semantics. Recover and validate before publication; fault test abrupt death before/after commit and sync. Reopening descriptions across restart would require a separate authenticated recovery protocol for stable IDs and live open references, including unlinked objects and offsets; defer it and keep old descriptors stale. Durable names do not imply durable handles.

## Ordered changes and gates (proposed)

1. **Fix readiness and distinguish failures.** Extend `kernel/src/ipc/vfs_registration/{chdir,stat,transport,inheritance}.rs`, `kernel/src/ipc/vfs_resources.rs`, and launch gates in `kernel/src/process/spawn.rs` and `kernel/src/arch/x86_64/syscall.rs`. Verify authenticated delivery, delayed acknowledgements, launch, stale caller and VM, service replacement, timeout and capacity separately on host and QEMU. Keep ENOENT as evidence of successful dispatch.
2. **Build a complete service contract under host tests.** Extend `ipc/src/vfs_rpc/{registration,file_transport,stat_transport,chdir_transport}.rs` (add a bounded namespace transport module) and `services/vfs_server/src/{runtime.rs,runtime/control.rs,directory.rs,namespace.rs,open.rs}`. Implement anchored existing/create/exclusive/truncate open, mkdir, rename/replace, unlink/rmdir, access, attribute changes, and directory streams. Extend `sunlight-fs/src/{vfs.rs,vfs/anchored.rs,ramfs.rs,policy.rs}` only where backing semantics are missing. For hard/symbolic links and metadata timestamps, implement correct object and permission semantics where supported; explicitly gate unsupported mount features. Test confined traversal, symlink limits, both-parent denial, atomic competing O_EXCL and rename, stable inode/stat/fstat agreement, open-unlinked lifetime, directory cookies under mutation, full queues and failed reply cleanup. Do not wire a lone mutation into the shared live root.
3. **Wire one complete mount slice.** Update `compat-linux/src/{lib.rs,abi.rs,open_flags.rs}`, `kernel/src/arch/x86_64/syscall.rs`, `kernel/src/process/{fd_table,mod,spawn}.rs`, and `kernel/src/ipc/vfs_registration/{file,chdir,stat,transport}.rs`. Use typed directory tokens and per-description cursors, service getcwd from retained ancestry and fchdir from retained fd. Populate consistent device/inode, timestamps and link counts from the same backend. Audit copy faults and fd reservation/close; unsupported operations on that mount fail explicitly. Start with a dedicated service-only test mount with no K shadow. QEMU gate: two unrelated authorized processes observe create/stat/chdir/getcwd/open/readdir/rename/unlink immediately; dirfd survives rename, retained fd survives unlink; verify negative permissions, fake/stale tokens, exit and exec teardown, concurrent replacement and read/write/seek parity.
4. **Switch shared mutable paths together.** Inventory native shell, launcher/image loader and other kernel consumers via `KERNEL_VFS`, plus mount setup in `kernel/src/main.rs` and `services/vfs_server/src/main.rs`. Route every consumer of a transferred mount through its single authority or remove its access. Use clean activation or drain and freeze old writers, explicitly migrate state, and atomically publish the new mount; never silently leave the kernel shadow writable. Keep bootstrap seed and kernel-owned pseudo objects explicit; preserve private host-key/broker restrictions. Gate on unchanged boot, native and Helios regressions, shell creation visible to Linux, and generic repository primitives before `tools/test_helios_git.py`. Check local init/add/commit/status/log/diff/checkout individually. Clone/helpers that need process creation remain a separate compatibility gate.
5. **Prove service loss and then durability if required.** Extend `services/vfs_server/src/{main.rs,runtime.rs,runtime/control.rs}`, registration retirement, and backend/mount integration in `sunlight-fs/src/{vfs.rs,block.rs}` as selected. First prove fresh volatile restart, old fd/cwd failure and late reply rejection on QEMU. For a persistent backend, prove crash ordering, recovery and fsync behavior across process restart and reboot with a writable test disk. Neither gate should rely on transparent fallback.

Production migration, guest replay and restart validation were not performed during this investigation.
