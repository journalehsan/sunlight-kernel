# KLC-1B — Service image retirement and VFS settlement

**PARTIAL — IMPLEMENTED and HOST_VALIDATED.** Exact last-owner exit still settles embedded-service registrations. Successful live exec now settles the *private VFS backing* of that exact former image. Endpoint withdrawal alone leaves remote ownership outstanding. The change is suitable for review as a provisional VFS-L1 dependency; production integration remains blocked and **NATIVE_QUALIFIED: NOT_RUN** on UP and SMP.

## Independent review and production change

- **Last owner and authority fence.** [Scheduler reaping](../../kernel/src/sched/mod.rs) excludes current or queued tasks and pinned stacks, waits for every VM borrower to reach Reaped, and requires an inactive VM. It withdraws VFS admission before reclaim, removes queued PID references and owned endpoints, closes correlated endpoint callers, removes reply targets, drops task-local IPC and capabilities, then transitions the task to Reaped and issues the proof under scheduler serialization. Borrower cleanup cannot issue it. The proof snapshots PID, incarnation and VM generation before invalidation. Forced termination can withdraw early; it uses the same reaper and does not itself prove completion.
- **VM lifetime.** [Root reclamation](../../kernel/src/process/address_space.rs) asserts no active CPU and no same-root/generation ownership in the persistent retirement journal. It releases private leaves and the ledger, frees the root and invalidates its identity. A precondition failure cannot produce a proof. This preserves the current fail-stop policy. Phase 0 did not identify an early or wrong-image exit completion in the audited domain.
- **Lease lifetime.** With [boot-only VFS provenance](../../kernel/src/main.rs), the mounted namespace, policy `Arc<DirectoryPair>` pins, remote lease table and file-owner table live in the embedded [service runtime](../../services/vfs_server/src/runtime.rs). Requests are copied and carry numeric identity/scope, not transferable pairs or backend ownership. Policy and file tables can share those pairs inside the image; private heap and anonymous mappings disappear on reclaim without running destructors. Shared boot data, peer SHM/memfd references, delivered copies and their effects, external resources and persistent state follow their own owners. A retain does not roll back filesystem mutations. This reasoning would need review before admitting a service with externally owned lease backing.
- **Previously missing exec settlement.** [Live exec](../../kernel/src/arch/x86_64/syscall.rs) permits the boot VFS image to replace itself if the ordinary exec preconditions hold. The early service-manager restriction is on a different role; exec by a borrower or a VM owner with unreaped borrowers is rejected. [Image preparation](../../kernel/src/process/spawn.rs) commits only after load and stack preparation succeed. The live error path restores the old root and saved roles/personality; it does not withdraw VFS, clear the role or issue completion. Early resolution/format failures also precede withdrawal. The new [typed exec proof](../../kernel/src/process/exec_retirement.rs) is constructed only in the live success branch after exact VFS withdrawal and clearing boot provenance, and is usable only after the old root is reclaimed. Before this change, an unanswered retain remained owned after exec and even exit of the successor would name the wrong VM generation. The mixed host regression observes that retention before delivery of the new proof.
- **Exec scope.** PID and incarnation survive; the VM generation changes. Exec revokes recipient grants, cleans old SHM mappings, and retires captured ordinary, deferred and outgoing IPC call authority via the syscall tail. It does not generally destroy PID-owned endpoints or all queued IPC. Non-CLOEXEC descriptors survive under existing transfer/rekey rules; other independent transferable capabilities or peer references can survive. The replacement loses VFS provenance and cannot use the old epoch even if an endpoint still names its PID. The proof certifies the private VFS backing only and does not stand in for IPC teardown, FD transfer success, or general task retirement.
- **Collection.** [Registration runtime](../../kernel/src/ipc/vfs_registration.rs) accepts the exit and exec proofs through separate typed entry points. Each marks only retired rows whose exact owner image matches; an image may own multiple retired epochs. Individual replies still require the precise registration, epoch, operation/request and scope; a wrong epoch is not a form of image completion. A retired row can drain through authenticated settlement and caller/file barriers, or through private backing retirement after every installed local binding user drains. Pending results and descriptor ownership outside the row remain with their existing owners. Duplicate proofs are harmless; unrelated rows survive. Proof delivery scans four fixed rows without waiting, sending IPC or allocating a record. Exec already acquires the runtime under scheduler and PMM for withdrawal; settlement uses that lock order after releasing the broker. There is no proof history; at most four row-scoped markers and 64 retain/caller slots of each kind per registration.

## Lifecycle coverage

“Epoch retires” means admission is fenced; an exact old row can remain for settlement. “Binding drain” means all local consumers of installed bindings have released their references. Accepted work below distinguishes new installation from possible service-side effects.

| Transition (production source) | Process and old image | Epoch and endpoint | Accepted IPC, leases and local users | Proof, slot recovery and PID |
|---|---|---|---|---|
| Individual borrower exit (`sched/mod.rs::reap_process_resources`) | Task identity ends; owner and VM survive | Borrower endpoints retire; image owner's endpoint/epoch can survive. A raced worker chdir may retire the epoch conservatively | Other tasks' work, owner leases and local binding users can survive | No image proof. Ordinary authenticated settlement only; borrower slot reuse follows scheduler rules |
| Last-owner exit (same reaper) | Process ends; retained scheduler identity persists as required; old VM reclaimed | Old epoch fenced and owned endpoints revoked | Queued owned work removed, correlated calls closed; delivered copies outside the image may survive. Private leases end and local users may remain | Exit proof and binding drain or earlier acknowledged settlement; no new PID predicate |
| Successful live exec (`sys_exec`, `process/spawn.rs`) | Same PID/incarnation; old VM reclaimed | Old epoch retires; ordinary endpoint ownership can survive, old VFS control cannot | Captured call targets retire; ordinary queued/delivered effects and independent resources can survive; private leases end; local users may remain | Private VFS exec proof after reclaim and binding drain; no PID release |
| Failed exec (same paths) | Same process and old VM | Epoch and endpoint unchanged by exec | Previously accepted operations, leases and binding users remain valid under existing authority | No proof or exec-triggered recovery. The old image can later settle or qualify on exit/exec |
| Endpoint-only withdrawal (`endpoint_destroy`, `Runtime::retire_endpoint`) | Process and old VM live | Exact endpoint dies; epoch retires; other endpoints may survive | Endpoint queues/waiters close. A previously delivered copied retain, directory lease, and local users can survive | No proof. After endpoint destruction that epoch cannot authenticate over a different endpoint; later qualifying exec/exit can recover after local drain. No PID release |
| Registration replacement (`register_service`, `Registry::register`) | Old and new owner may be different images; same image can have older epochs | Requires the active epoch to retire; new epoch is distinct. If old endpoint remains live, only exact old authentication can settle | Old delivered work, leases and binding users may remain; successor can neither install an old result nor certify cleanup | Publication is not proof. Old-image proof applies to matching retired rows even after publication; cap remains four; no PID policy change |
| Service restart (`main.rs` boot provenance) | Would need a newly authorized image; general launch/exec supplies no boot role | Existing code can fence old epoch; production successor authorization unavailable | Any retained old work follows its owner until qualifying settlement | Old proof is independent of restart. Host fixtures model authorized replacement; production restart is unsupported. Scheduler owns any eventual PID reservation |
| Forced termination (`terminate_process_by_pid`, fatal/group paths) | Task may still be running or pinned when requested; VM survives until last-owner reaper | Admission can fence during termination; endpoint teardown follows existing scheduler path | Closure/retirement can precede VM destruction; delivered work and private leases may still exist until reap; binding users may outlast it | Qualifies only when normal exit proof gates pass; no new termination or PID policy |
| Deferred reclaim (borrowers, pins, TLB and retirement journal) | Retiring image/identity retained until required gates pass; journals can retain exact VM ownership or fail stop | Early fence possible; applicable endpoint teardown still required for exit | Resources not yet proved disposed stay owned; unrelated external resources and binding users can persist | No proof during deferral or failed reclaim; recovery only on a qualifying later observation, with no elapsed-time bound |

The endpoint-only liveness limitation belongs to the **VFS service lifecycle owner**. A still-authenticated retired epoch can finish its normal refusal/release/barrier protocol. Once its endpoint is destroyed, removing a service-local pin alone cannot tell the kernel what happened to an unanswered acquire. The current terminal path is authorized retirement of that image (exit, or qualifying exec). A live image can indefinitely retain an unresolved epoch; repeated abandonment can exhaust four rows and fail new registration closed. This is accountable retention and a real availability limit. There is no policy to kill on deadline and no new cleanup receipt or supervisor.

## Identity and accounting

VFS registration rows require PID + process incarnation + VM generation, the owned endpoint ID and registration epoch, and the specific request/receipt and caller scope. Endpoint allocation and registration epochs use checked counters; ordinary dynamic PID allocation uses checked max-retained-PID plus one under the lifecycle lock, including reaped rows. The existing `pid.rs` regression demonstrates the arithmetic, not guest reuse. The normal scheduler insertion path honors core and stack references, child wait and service reap watcher state; supervision and resource ledgers retain their own exact keys. VFS rows do not keep a process reference or reserve a numeric PID. Numeric PID-only consumers such as scheduler waits and broker/shard cleanup still follow existing release gates. Do not change PID allocation or general reuse eligibility based on settlement.

For VFS-L1, reserve an opaque creation transaction and numeric PID before exposing any exact target to the service. Preserve the final image identity, the immutable registration/endpoint/epoch, the request identity and the pinned parent scope. One serialized terminal take transfers local cleanup ownership and defeats late commit. Release the private reservation only after unpublished resources are destroyed, scheduler/visibility and numeric-only references cannot observe the private child, and late remote receipts/continuations have either settled or moved to bounded exact-identity compensation with no numeric-only reference or route to publication. Keep scheduler/supervision reservations where they apply. This describes the proposed interface; KLC-1B does not implement that reservation or release.

The 100-cycle exit regression and 100-cycle mixed regression each return to one active row after every cycle. Mixed cycles cover 75 modeled successful execs (50 with endpoint withdrawal), 25 withdrawal-then-exit cases, a failed-exec control on every cycle and 50 delayed binding releases. The replacement retains its own request until the exact refusal. A separate test settles two old epochs of one image while preserving a different retired image. Before completion, unresolved rows retain the obligation; with a pinned binding a matched row stays until the final drop. Tests cover stale replies, wrong incarnation/VM/epoch, incomplete proof, duplicate completion and simulated identity/endpoint reuse. Some endpoint ownership survives modeled exec until the fixture replaces the process; broker tests separately verify independently transferable/shared authority. Registration and obligation counts are measured in the host runtime; endpoint inventories, image teardown, event delivery ordering and process identity transitions are fixture inputs. Native endpoint/shard cleanup, PMM, external resource, deferred journal and PID census, and concurrent retirement/ack races are not measured by the mixed tests. The standalone resource retirement suite tests journal deferral, exact completion, quarantine and retained ownership separately.

## Validation and integration decision

See [results](klc-1b-results.json) and `target/klc-1b/`. The registration harness compiles the production registration/authentication/settlement code, both proof gates and mounted service runtime. Tests simulate scheduler, broker endpoint inventory, copy boundary, VM load/rollback/reclaim and identity transitions. The real broker/grant, PID arithmetic and retirement tests provide separate controls. Transaction/session and mmap features compile in the freestanding binary; this is build evidence only. The unchanged ordinary gate stops before build and QEMU at **71 references, four outside baseline**. The four sites are [private file mmap, statfs capacity, procfs mountinfo, and StorageCtl FAT mount](../filesystems/helios-vfs-authority-audit.md). No KLC-1B ownership growth.

The VFS reports require normal boot and native lifecycle evidence for promotion. They contain no approved exception for consuming host-only evidence as production readiness. The primitive may be reviewed and kept in the worktree. **INTEGRATION_READY: blocked pending the project owner's decision and the pending-child implementation prerequisites.** The decision is whether to authorize an explicitly unqualified, host-only VFS-L1 pending-child integration slice while preserving the existing authority fence and guard, with no default enablement or production promotion until native qualification. If authorized, first build a bounded private transaction with exactly-once commit/cancel and local reclaim; use only authenticated settlement and the defined proofs, fail closed elsewhere, then close the ownership findings and run the unchanged native gates. Exit-only KLC-1 is sufficient as a provisional settlement dependency only if exec and endpoint loss are treated as safe cancellation with potentially indefinite retained cleanup. KLC-1B removes that exec-specific retention for the proven embedded backing; endpoint loss remains independently unqualified for completion.

An alternative owner decision is to defer the four legacy paths and their dependent features in an explicitly reviewed scope reduction until userspace equivalents exist. That needs a caller/dependency and compatibility review, a defined unsupported/error contract at the public boundaries, and an unchanged guard that actually passes on the resulting source. A feature switch alone does not remove a source-reference finding. No deferral, source guard exception or feature removal is part of this phase.

| VFS-L1 pending-child case | Readiness |
|---|---|
| Successful namespace acknowledgement | **Safe but awaiting integration.** Authenticate and revalidate before binding commit; perform separate atomic publication. |
| Service refusal | **Safe but awaiting integration.** Exact refusal settles the retain; the creator must cancel and reclaim the unpublished child. |
| Timeout with service alive | **Safe cancellation with retained cleanup obligation.** Timeout ends publication eligibility, not uncertain remote ownership. |
| Last-owner exit before acknowledgement | **Safe but awaiting integration; native qualification pending.** Exact private proof and binding drain can settle independently of child reclaim. |
| Endpoint withdrawal before acknowledgement | **Safe cancellation with retained cleanup obligation.** Preserve the row until authenticated settlement where still possible or qualifying image retirement. |
| Service exec before acknowledgement | **Safe but awaiting integration; native qualification pending.** Qualifying embedded private exec settles only the old image. Other transitions retain cleanup obligations. |
| Replacement service publication | **Safe and implemented for epoch isolation; blocked by an architectural dependency for native restart.** A successor cannot adopt the predecessor's transaction or certify its cleanup. |
| Late acknowledgement after cancellation | **Safe but awaiting integration.** The existing abandoned-retain path only permits compensation; exact pending-child cancellation/publication arbitration remains to be built. |
| Parent exit during pending creation | **Blocked by an architectural dependency.** VFS-L1 needs a parent-bound transaction, visibility fence and explicit ownership transfer to local cleanup. |

Recommended next phase: obtain the provisional-integration decision, then implement the private creation reservation and commit/cancel arbiter under host gates. Require unchanged ordinary boot plus UP/SMP evidence of refusal, delay, both terminal orders, real exec/exit and authorized replacement, first namespace use on dispatch, and full repeated resource accounting before promotion. VFS-D1 remains blocked.
