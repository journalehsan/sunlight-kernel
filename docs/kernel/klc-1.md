# KLC-1 — Last-owner service image retirement

**PARTIAL.** The scheduler produces kernel-private completion for the last-owner exit of an exact image. VFS uses it to settle obligations backed by the embedded service's private image once local binding users drain. Host recovery passes. Ordinary boot fails at the existing ownership gate, and native UP and SMP are NOT_RUN.

This records the exit-only baseline. [KLC-1B](klc-1b.md) preserves the exit proof and adds a separate, narrower proof for the embedded service's private backing on successful live exec. Endpoint-only withdrawal still cannot certify disposition; native and VFS-L1 integration gates remain open.

## Production lifecycle inventory

The scheduler serializes process transitions and process-slot reuse. The table identifies the additional locks and the residual resources at each boundary.

The producer uses `RecipientIdentity`. The consumer projects completion onto a still-owned, retired `Registration` whose owner matches all three image fields. Each row already carries its endpoint and boot-monotonic epoch. Completion covers all retired registrations of the exiting image, including earlier endpoints, because the image and all its owned endpoints have been torn down. The VM generation serves as the image instance discriminator, so no extra retirement sequence is needed. Exec has separate authority and ownership transitions and emits no last-owner exit proof.

## Lease ownership and settlement

Only the embedded boot image receives `trusted_vfs_service` in production (`kernel/src/main.rs`). Exec removes the role and new process constructors default to false. `services/vfs_server/src/main.rs::_start` owns the service runtime and mounted namespace, and `runtime.rs::Entry` owns the policy and file table. `policy.rs::request` acquires an `Arc<DirectoryPair>` through the lease table. The pair holds local handles and an Arc to the same process's backend (`directory.rs`). The mounted root is local RamFs, and service payload pages use private anonymous mappings via `init_tmpfs_pages`. The boot share page supports a separate adapter. It carries boot contents and no mounted directory pair or retain table state. Retain copies numeric identity and scope data, with no serialization of a directory pair, backend handle ownership or lease-bearing shared mapping. Any other references to that pair in policy or file tables are within this same image. A service killed by the kernel need not execute Rust destructors for the private backing to cease to exist.

VFS synchronously records the proof on matching retired epoch rows under RUNTIME. Collection takes a row only after all its published bindings have been retired and drained to the runtime's final reference. Preparing snapshots have no installed binding. The take disposes of unanswered, queued and unacknowledged release bookkeeping and service-local caller/file barriers exactly once. Those barriers refer to objects and owner keys in the destroyed service, including the source and destination keys of any in-service transfer. Runtime withdrawal has already invalidated that epoch's file publications. Surviving kernel descriptor tokens and pending kernel result ownership follow their existing contracts. Slot recovery grants no permission to use a token in a different epoch. Production file routing remains deferred separately.

There are at most four completion markers, carried by outstanding registration rows. Admitting a row establishes its interest before any lease publication. A completion can arrive before local consumers drain and remains recorded in the row until collection. Cleanup, reconciliation and later admission can collect without issuing a second event. Duplicates and mismatches leave other rows intact. Existing authenticated settlement can release interest before completion. A new obligation cannot register retrospectively against an exited image. There is no replay history or general subscription for arbitrary late observers. Future consumers with external resources need a separate authoritative disposition from the actual owner, including any existing journal record or shared backing reference.

The path adds a scheduler → runtime acquisition already used for withdrawal. It acquires RUNTIME after releasing the shard, broker and PMM guards, makes fixed-array scans and does not ask the retired image for a response. The reaper continues to honor its existing scheduler, TLB and resource gates. Event delivery itself needs no retry, allocation or userspace participation. Local binding drain can delay collection. No elapsed-time bound, post-failure recovery, complete PMM/PID census or independent SMP progress guarantee was established. See [KFP-1](kfp-1-forward-progress-audit.md) and [KFP-2A.3](kfp-2a3-retirement-lifecycle-closure.md).

## Validation and integration

- The unchanged historical component fixture reproduced four unanswered acquired retains and rejection of the next registration. The service lease table in that fixture uses a unit payload.
- The corrected full-capacity test recovers exactly one slot and preserves three independent outstanding rows. The 100-cycle production transport and service-runtime test acquires a mounted-directory retain before its reply, queues another retain, withdraws, rejects incomplete proofs, and verifies exact-image collection, duplicate completion and stale acknowledgements across simulated PID and endpoint reuse. Each cycle leaves just the live replacement row. The reply-first test retains an installed binding across completion and independently completes a second image before draining the first.
- These tests use production registration, retention, authentication and collection functions and the production proof constructor. Scheduler transitions, endpoint broker state, proof inputs, copy boundaries and VM destruction are simulated. The tests exercise competing serial orders rather than a kernel concurrency witness. Actual queued shard IPC, reclamation failure, transfer of shared resources and peer progress are NOT_RUN in the integrated KLC-1 path. Existing IPC and retirement tests independently exercise queue cleanup, deferred references and retirement journal ownership/failure contracts.
- IPC 168 library tests plus 9 integration tests, VFS service 47, registration 92, descriptor 18, kernel host library 213, standalone retirement 21, and scheduler host controls pass. Kernel transaction/session and mmap feature checks pass. The first mmap command used an incorrect launcher path, which was corrected to the existing built fixture.
- The unmodified ownership guard still reports 71 references and four outside its reviewed baseline. Ordinary boot fails before QEMU. The dependent UP/SMP gates are NOT_RUN. The existing embedded role assignment also provides no production restart path to qualify replacement authentication end to end.

VFS lifecycle qualification requires native evidence. The ordinary gate blocks that evidence on four existing ownership findings, while the ownership migration depends on unfinished VFS lifecycle work. The reviewed VFS reports require native validation for promotion and provide no exception that qualifies an ordinary boot with the guard failing. Keep the implementation and source-bound evidence in the worktree as provisional engineering work. Keep L1A and L1 blocked for qualification and pending-child integration. The proposed review sequence is to admit only this lifecycle primitive for provisional integration, finish the prerequisite lifecycle work under host gates, resolve the existing ownership findings through the reviewed ring-3 migration, then run the unchanged boot gate and qualify UP/SMP with an authorized service replacement path. The guard, allowlist and reviewed baseline stay intact throughout. VFS-D1 stays blocked.

Exact logs and machine-readable statuses are indexed in [klc-1-results.json](klc-1-results.json). L1A can review the implemented exit-only recovery path now. Its native and exec/endpoint-only retirement cases remain open.
