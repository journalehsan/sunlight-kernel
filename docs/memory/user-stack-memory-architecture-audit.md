# User stack memory architecture audit

Keep the 2 MiB main user stack window and qualify demand backing behind an opt-in switch. The earlier [service census](system-services-memory-footprint.md) counted 16,896 private stack frames (66 MiB) across 33 BIOS service leaders. The new eager-image measurements below separate physical backing from page touches. They do not qualify demand backing or sustained 512 MiB operation.

## Current contract

| Path | Reservation, backing and lifetime |
| --- | --- |
| Early native init, VFS and TTY | [Boot setup](../../kernel/src/main.rs#L940) calls `map_user_stack` and sets initial RSP to the stack top. The boot entry has no exec argument block. |
| Native spawn, Helios image and exec | [Common image builder](../../kernel/src/process/spawn.rs#L435) loads ELF, maps 512 stack pages, and builds the startup block. Linux personalities add ELF, identity and page-size auxv; the feature-gated interpreter handoff adds `AT_BASE`. Exec stages a replacement address space and restores the old image on prepublication failure. Old and new physical backing can coexist during the transition. |
| Main stack layout | [Layout](../../kernel/src/process/layout.rs) fixes the window at `[0x00007fffffdff000, 0x00007ffffffff000)`. All 512 usable pages are zeroed, present, user RW/NX, owner PID private frames. The system/owner-managed ledger region cannot be changed by ordinary user unmap, replace or protect. The top excludes the last canonical user page. An absent page below the window provides a boundary only where it stays unmapped: `map_user_stack` registers the usable window, with no separate protected guard reservation. The static TLS fixture places TLS two pages below the floor. Audit neighboring mappings before promising a permanent lower guard across all images. |
| Native worker | [libc thread startup](../../sunlight-libc/src/thread.rs#L73) eagerly mmaps a default 2 MiB or caller-sized rounded RW anonymous stack and separately maps TLS. It writes entry and argument at the aligned top and passes that RSP to the kernel. `MAP_NATIVE_THREAD` preserves allocation boundaries (`NO_MERGE`); it does not create a stack guard. The owner address space accounts for the frames. libc unwinds failures and unmaps after join or the detached-reap protocol; the syscall accepts a caller-supplied stack. |
| Helios worker | [Linux clone](../../kernel/src/arch/x86_64/syscall.rs#L3486) validates a supplied writable stack endpoint and keeps the shared VM; the runtime owns the stack mapping and any guard. The Linux `MAP_STACK` bit is translated as advice. Eligible Linux anonymous mappings already support demand backing; this does not make them kernel-owned stacks or grant grow-down semantics. Preserve libc-created guards and caller-owned buffers. |
| Kernel stack | Each admitted task has a separate 32 KiB kernel stack inside the prebacked 16 MiB kernel heap. These are scheduler/syscall continuations, never part of stack frame savings. Reclamation follows outgoing stack pin retirement independently of user mappings. |

The current [fault handler](../../kernel/src/arch/x86_64/interrupts.rs#L577) tries a ZRAM marker, anonymous demand backing, then CoW for writes. There is no main stack growth route. Unresolved user faults terminate with status 139; unsupported kernel faults are not recoverable user growth. [User-copy validation](../../kernel/src/memory/user.rs#L150) may back eligible anonymous pages before copying, then uses the physical alias. The main stack is outside [reclaim eligibility](../../kernel/src/memory/swap.rs#L464): candidates must be tracked anonymous pages with owner and PTE matches, and trusted swap/display processes are excluded. Native thread stacks use the anonymous path and can be candidates subject to those rules. Missing virgin pages, swapped markers and permissions failures are distinct states.

## Measurement

Fresh compressed-module QEMU 11.1.3 TCG guests used two vCPUs. The audit kernels sample present user leaves, PMM owner and class, and x86 accessed/dirty bits at existing boot and document checkpoints and TLS overlap. Logs and exact instrumented source patches are under `target/user-stack-audit/`. No application binary was changed for stack measurement. See the [results JSON](user-stack-memory-architecture-audit-results.json) for per-PID data and run provenance.

Accessed counts are cumulative in stable eager main-stack PTEs. Deepest accessed page is a page-granular touched-address high-water mark; it is neither exact minimum RSP nor live bytes. A frame can be reserved in a function without a touch, and a deep reference can skip untouched pages. Loader and kernel copies through the direct map do not set user leaf A/D bits. Worker observations also depend on resident PTEs at sample time; swapped or removed leaves can erase history. The sampler holds scheduler and PMM locks but doesn't stop sibling CPUs, so each row is a bounded observation rather than an atomic VM-wide snapshot. It doesn't clear A/D bits or force shootdowns.

The four extended runs each found **32 idle leaders with 16,384 private stack frames (64 MiB)**, plus the document worker's 512 frames. The earlier optical-only BIOS census had 33 leaders. The new fixture boots the USB mouse service, which exits after reporting no usable xHCI boot mouse. It does not remove any service or filesystem resource. Across the 32 idle main stacks, 417 pages (1.63 MiB) had the accessed bit set. The sum of the 32 depth high-water marks was 423 pages (1.65 MiB). That leaves 15,967 eagerly backed pages without a recorded user access at idle; this is scope for investigating avoidable backing, not a safe decommit count.

| 512 MiB BIOS | 19,256 | 19,256 | 15,043 | 6,442 |

At every parsed extended checkpoint, free frames plus physical classes equal managed frames. The boot-to-recovery low water is a running PMM counter, not the minimum of phase snapshots. The TLS figures are checkpoint snapshots; they do not isolate a TLS-specific PMM delta.

| Process | Idle deepest touched page | Bounded workload observation |
| --- | ---: | --- |
| `sunlightd` | 154 (616 KiB span) | Startup/idle only; already exceeds 512 KiB |
| VFS | 29 (116 KiB) | Namespace and 2 KiB shared read at boot; no isolated saturation measurement |
| TTY | 16 (64 KiB) | 28 (112 KiB) after shell login, tabs and verified TLS client work |
| TLS | 3 (12 KiB) | 5 (20 KiB) with two verified sessions, both payloads read back and sessions closed |
| Docserv leader | 1 (4 KiB) | 6 pages accessed, deepest page 9 (36 KiB span) during open/render/thumbnail workload |
| Docserv probe worker | 1 (4 KiB) | 1 page accessed at the RPC samples; 512 resident frames charged to docserv |
| Display/compositor service | 5 (20 KiB) | Same depth at interactive checkpoint; startup initializes the compositor, but no logged-in desktop rendering workload was exercised |

For 33 leaders, average commitment of 16, 64 or 256 KiB would save **65.48, 63.94 or 57.75 MiB** of gross stack frames, respectively. These are conditional scenarios; neither metadata nor page table deltas are included, and none is a prediction from the idle census. The 2 MiB worker is excluded. The actual gain depends on startup writes, chosen seed, first touches and whether the prototype commits intervening pages.

In a separate four-guest Helios run, `linux-echo` and the raw Linux threaded probe each exited successfully. Each leader had 512 private main-stack frames at exit and one accessed page. The echo startup block used 720 bytes from the stack top (2 arguments, 15 environment entries, 13 auxv pairs, from the logged RSP in the prior run); that includes bytes written by the kernel that A/D alone cannot count. The thread probe's supplied worker stack is outside the main window and was not measured. Earlier TLS-plus-Helios runs recorded a generic threaded-probe exit 1 once on 512 MiB UEFI and once on 512 MiB BIOS. The successful follow-up leaves those earlier failures unexplained.

To reproduce, apply the audit-only `extended.patch` or `helios.patch` to the recorded source, build the release kernel with `boot_resources,native_document_viewer` and the compressed VFS input, and package it with the same compressed resource module using `tools/make_hybrid_iso.sh`. The build logs and hashes are in the evidence directory and JSON. Run the corresponding `extended_gate.py` or `helios_gate.py` from the evidence directory with `PYTHONPATH=tools` from the repository root, `--compressed-boot --heap-overlap --tcg --cpus 2`, the recorded ISO and RAM, and `--uefi` for the UEFI guest. The patches and fixture copies are audit artifacts only.

## Proposed architecture

1. **Reserve before publishing.** Represent a protected main-stack window with a distinct backing policy keyed by address space generation, plus a separately protected lower guard outside the existing usable range. Verify that the guard and a suitable separation from adjacent mappings fit without changing the user limit; handle collisions as admission failures or keep that image eager behind the opt-in. Preserve the upper boundary. For the first experiment, evaluate a 4-page top seed for raw startup and a page-rounded exec seed covering the actual checked startup block, its alignment and top slack, with a 4-page minimum. Derive the full range before any copy: NUL-terminated argv/envp strings, pointer tables, terminators, auxv, 16-byte AT_RANDOM, padding and a 16-byte-aligned entry RSP. Keep native red zone and call alignment, Linux interpreter/TLS startup, and loader failure semantics. Do not infer a safe universal seed from this census.
2. **Commit only inside the reservation.** For user-mode non-present read/write faults, check canonical address, fault bits, VM identity, region ownership, permitted range and PTE state. Never grow on execute, reserved-bit, protection, CoW, guard or unrelated faults. Separate software-assisted stack writes for exec staging and signal delivery from normal syscall user-copy policy. Validate the full range and commit under explicit intent before copying or publishing a signal frame. Native delivery preserves a 128-byte red zone and handler alignment; [Helios delivery](../../kernel/src/arch/x86_64/linux_signal.rs#L100) also writes aligned FXSAVE and signal data and currently requires a normal stack. An installed alternate-stack descriptor does not prove general alternate-stack delivery. Preserve the current signal ABI and test page crossings, nested/unsupported delivery and failure paths. Ordinary copies into valid stack buffers must continue working; a kernel copy must never authorize arbitrary growth based on kernel RSP or extend a guard.
3. **Allow measured large frames without weakening bounds.** A one-page adjacency rule or fixed short distance from saved RSP is not compatible by default: large prologues, red-zone use, stack pointers passed to other threads and syscall/exception destinations can violate it. First evaluate sparse backing of any authorized page inside the fixed main reservation; reserve density and per-process physical use are bounded by its 512 pages. This preserves accesses the eager mapping already accepts. An unmapped guard catches accesses *to* it; a large RSP change can leap over it into another writable mapping without a fault attributable to the stack. A handler cannot detect all such leaps. Require coverage of native stack-clash probes in shipped binaries/toolchains, verify neighboring layout and reserved gaps, and test unprobed Helios binaries separately. Do not claim full guard-bypass prevention for arbitrary uninstrumented machine code. A contiguous commit frontier would make skipped pages resident and must be budgeted and measured separately.
4. **Allocate transactionally.** Under the existing VM serialization and scheduler→PMM lock order, recheck identity and leaf state, reserve frame and missing page tables, sanitize via HHDM, and publish a user RW/NX leaf only after success. Serialize two sibling faults; the loser validates the already-installed leaf and retries. Distinguish a concurrent install from a stale identity. Use the existing TLB publication/invalidation contracts across CPUs; never release a withdrawn frame before acknowledged retirement. Charge each leaf once as owner private, page tables separately, and absent reservations zero physical frames. Limit any direct reclaim with existing budgets, outside conflicting locks, and revalidate after a retry. On failure unwind private frames and newly empty tables, keep the reservation intact, and follow the current controlled user fault termination or syscall error path. Prepublication exec/thread admission failure must leave the original image or caller usable. Fault-time OOM is a new runtime failure surface even when admission succeeds.
5. **Keep current swap and lifecycle policy.** Initially exclude demand main-stack leaves from ZRAM, as today, and keep native/Helios anonymous policies unchanged. Never turn a swapped marker into a zero page. If opt-in swapping is later justified, qualify owner/incarnation checks, bounded direct reclaim, swap-in permission and content fidelity, no-progress under incompressible data, trusted service exclusions, slot retirement and independence from VFS. Keep worker stacks on their current ABI until a separate opt-in libc/kernel contract can identify the exact range and lifetime without taking ownership of arbitrary clone stacks. Teardown must distinguish never-backed, resident, and swapped pages; follow address-space retirement before freeing page tables and frames, and keep main versus borrowed VM and kernel stack lifetimes separate. Verify failed exec, peer-thread exit, detached join cleanup, and exit/exec under concurrent faults.

## Alternatives and qualification

| Model | Effect |
| --- | --- |
| Eager 2 MiB | Predictable first touch and startup admission failure, with 512 zeroed frames per leader regardless of use. |
| Smaller fixed stack | Immediate frame savings but shrinks usable ABI limits. A flat 512 KiB would fail the observed `sunlightd` depth alone; per-program sizing is brittle across workloads and updates. |
| Demand within the current window | Saves frames in proportion to pages never committed. Preserves the address limit, but shifts work and some OOM risk into execution, requires guarded publication, and exposes cold-fault latency. |

Start with better lifetime sampling (including terminal teardown, page/byte RSP witnesses, kernel-copy ranges, and active desktop workloads). Model region and allocation transactions, then qualify an opt-in main-only prototype with boot/raw entry, large args/env, large frames, ABI/red-zone and signal cases, checked user copies, permission and guard failures, concurrent first touches, OOM after partial page-table allocation, and exec/exit identity retirement. Require failure paths to return PMM identities to baseline without relying on caller return as retirement evidence. Preserve the compressed boot opt-in, adaptive document/TTY/TLS heaps, 16 MiB kernel heap, corrected frame accounting, ordinary services/resources, and the VFS migration prerequisites.

Re-run the four native configurations with matched eager controls and ordinary/compressed boot, 1/2/many vCPUs, document rendering, interactive TTY and PTY bursts, verified TLS overlap, VFS read/write and logged-in compositor interactions, and representative stock Helios CLI, threaded and terminal workloads. Measure per-phase free-frame minima, reserve/resident/swap counts, fault latency and workload progress over repeated concurrent runs. Add separate thread-stack and ZRAM phases only after the main-stack results hold. A bounded 512 MiB pass does not establish sustained operation.
