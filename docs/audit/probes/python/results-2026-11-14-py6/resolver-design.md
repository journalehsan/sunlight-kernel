# PY-6 design, recorded before implementation

Extend the existing Vfs, FileSystem and native syscall/client boundary. Do not create a filesystem service or parallel client. First add an explicit read-only metadata provenance/capability contract: native stored policy and object identity are separate, missing times are unavailable, FAT unsupported identities remain None. Tmpfs identity is stable only in this mount lifetime. MountInfo id qualifies local identity; neither handles nor FAT clusters are invented inodes. Existing 24-byte Stat ABI remains unchanged.

Add a bounded existing-path component walker on Vfs. Input cwd must itself be absolute and validated by walking its components. Walk each component before processing subsequent dot/dot-dot, require current directory type and Execute permission using existing Credential/check_permission policy. Preserve whitespace, enforce 255-byte paths and a bounded input; repeated separators are accepted. FAT spelling is recovered through backend directory enumeration; no case folding applies to tmpfs. Mount dispatch happens at each component and parent search is checked before entering a mounted root. Current namespace is the global VFS; no new namespace or capability grant exists. Output is an observation, not a pin or authorization token. All steps occur under one existing mutable Vfs borrow/global kernel VFS lock, with no scheduler acquisition or service IPC inside the walk.

Expose a native resolve syscall with bounded NUL-terminated input/output and explicit errno. Add a small shared Rust client using the existing libc syscall wrapper. Use it for native shell directory navigation; avoid broad UI migration until raw paths can reach this authority. A canonical query never grants read/write access; existing policy checks remain on operations. No lexical realpath implementation.

Symlinks need a distinct inode type, immutable target storage, quotas, mutation and traversal integration across every match on FileType, followed by a versioned ABI. Do not encode FAT links. Complete POSIX stat cannot be exported with mandatory fabricated times/identity. FAT's pathname-backed write/truncate and cached cluster/size need a shared inode/open-description lifetime before full fstat can be qualified; stop that affected contract if it requires broader storage changes. A read-only canonical path operation can proceed independently. Symlink and POSIX gates remain blocked until actual implementations and native tests exist.

Concurrency: global VFS serialization stabilizes each walk against VFS mutation but cwd/credential snapshots and later operations can race. Textual cwd does not pin renamed/deleted directories. Existing fd generation wrap and FAT unlink/reuse require negative probes; do not claim descriptor safety from successful simple tests. A future handle-relative resolver needs genuine pinned directory identity, not handle_path reconstruction. Avoid widening global locks or introducing synchronous IPC.

Validation: reproduce baseline; host filesystem/FAT tests and focused resolver/metadata negative tests; native syscall fixture for existing/missing/file-as-directory, dot/dot-dot, repeated separators, whitespace, buffers and relative cwd; real shell probes on 1/2/4 CPUs. Rebuild and repeat prior native C/C++/functional/lifecycle/oracle/TCP matrix on final source. Repeat pinned 180-object CPython configure/compile. Files click-driven comparison must be NOT_RUN unless actually exercised. Preserve failures and exact source bindings. Gates requiring missing features must not pass.

## Demonstrated application build dependency

The actual native-svg Files build fails because native-std stdio formatting references locale::ctype_is_utf8 while locale is gated to native-c. Broaden that module gate to native-std (native-c already implies it); this reuses the existing locale owner and restores the configured application build. Preserve the original failure log.
